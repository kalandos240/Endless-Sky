Условия договора конкретного аккаунта РСЯ требуют отдельной проверки.

Запрошен интервал 2 минуты 30 секунд; выбран Яндекс.

ID межстраничного блока, предоставленный владельцем: `R-M-20312738-1`.
ID зафиксирован для будущего подключения; тип и статус блока в кабинете
программно не проверялись. Для разработки сначала используется тестовый блок,
боевой ID не означает автоматического включения рекламы.

**Текущий статус: написан опциональный SDK-адаптер для тестирования.**
Обычная сборка без рекламы использует пустой адаптер: SDK и рекламные сетевые
разрешения в неё не добавляются. Тестовый режим явно выбирается при сборке:

```sh
python3 tools/prepare_android.py
cd android
./gradlew -PesAds=yandexTest :app:assembleDebug
```

Это режим локальной проверки, только с `demo-interstitial-yandex`, а не с рабочим
ID владельца. Release в этом режиме запрещён задачей Gradle. CI проверяет
компиляцию Java и слияние manifest для SDK, но не собирает и не публикует
рекламный APK. Для распространения комбинированной сборки вопрос лицензий
остаётся открытым. На физическом устройстве адаптер ещё не проверен.

Проверка 31 октября 2026 прошла успешно: [CI run 41191469067](https://github.com/kalandos240/Endless-Sky/actions/runs/41191469067).
Обычный APK собран и проверен (четыре arm64-библиотеки, SDL и пять JNI-функций,
ресурсы, подпись v2). Для `yandexTest` против настоящего SDK 8.6.0 успешно
выполнены `compileDebugJavaWithJavac` и `processDebugMainManifest`; это проверка
компиляции и manifest, а не доказательство показа рекламы. Исходный commit:
`0d5d7cfc52fb48b7b67414505e77a25cd3b1021e`.

SDK закреплён на версии 8.6.0. Автоматическая инициализация отключена; адаптер
инициализирует SDK вручную, с отключёнными user consent и location tracking.
Это тестовая настройка, не готовый интерфейс согласия или политика данных для
публикации. Сторонняя медиация и дополнительные рекламные форматы не подключены.

## Политика показа

- Первый показ возможен после 150 секунд активного использования в рамках сессии.
- Показ только в явной естественной паузе: переходе в меню или завершении игрового
  действия. Истечение таймера во время боя откладывает возможность показа.
- Сворачивание приложения и просмотр объявления не засчитываются в интервал.
- При отсутствии готового объявления игра продолжается. Пропущенные возможности
  не накапливаются; несколько объявлений подряд не показываются.
- После успешного показа и закрытия начинается новый интервал 150 секунд.
- При ошибке показа — не менее 30 секунд активного времени до повторной попытки.
- Старые и повторные callbacks не должны закрывать новое объявление.

Android-адаптер использует `SystemClock.elapsedRealtime`, UI-поток и lifecycle
Activity. После шага игровых окон нативный код публикует номер перехода в
`MenuPanel`; загрузка игры, диалоги и ввод имени пилота такой переход не создают.
Адаптер проверяет переходы каждые 250 мс, повторно проверяет номер перед показом
и отпускает сенсорные команды. Если объявление ещё не готово, оно не показывается
позже поверх того же меню: следующая возможность — новый вход в меню.

Игра уже приостановлена главным меню; Activity/lifecycle SDL должны приостановить
native-поток и звук при открытии рекламной Activity. Это поведение, включая
гонку с быстрым выходом из меню, ещё нужно проверить на устройстве.
Сохранение бюджета между перезапусками пока не реализовано.

## Что требуется для настоящей рекламы

1. ID блока получен: `R-M-20312738-1`. При интеграции проверить, что это активный
   interstitial-блок нужного приложения. Пароли и токены аккаунта не требуются.
2. Подтверждение условий распространения комбинированного APK. Код игры GPL-3.0-or-later;
   SDK Яндекса использует собственное лицензионное соглашение. Совместимость не
   установлена. Наличие публичных примеров SDK не делает сам SDK GPL-совместимым.
   Исключение к лицензии чужого кода нельзя выдать от имени владельца этого порта.
3. Проверить на устройстве тестовый адаптер: offline, ошибки загрузки/показа,
   возврат из объявления, сворачивание, звук, короткий вход/выход из меню. После
   разрешения вопроса лицензии подготовить раскрытия о данных, настройки согласия
   и отдельное включение рабочего ID. Боевые показы сейчас не предусмотрены.

На текущем этапе дополнительных рекламных форматов и сторонних трекеров нет.
